Increment 3 · Protocol completeness

HALO

Harness for Agent Lifecycle & Oversight. A generic, enterprise-grade agent runtime — a halo of oversight (gate, audit, human review, kill switch) around every agent decision. Language-neutral protocol; vendor-neutral runtime (repo agent-harness). A peer of APEX, EEIK, and Aether.

The harness makes agent execution safe, governed, observable, and reproducible — whatever LLM, memory store, or tools an agent uses, and whatever the host language. It is a generic implementation of the "agent runtime" that the Aether Intelligence Engineering Lifecycle (AIEL) specifies but does not build. Products consume it; it consumes nothing from them.

What the harness owns

Typed envelope

One AgentInput in, one AgentOutput out — the boundary where controls apply.

Authority + decision

Static capability ceiling (OBSERVE…BLOCK) vs. dynamic outcome (ALLOW…DEFER).

Confidence gate

Centralized, non-disableable: confidence < 0.8 → autoEnforced=false → human review.

Tool registry

Default-deny, runtime-enforced allowlists. No wildcards. Violations are security events.

Orchestration

Pipeline, Fan-out, Supervisor+Workers (supervisor holds no tools), Debate.

Pluggable ports

LLM, ToolRegistry, Policy, Audit, HumanReview, Observability, Memory, KillSwitch.

The invocation, gated

AgentInput ──▶ [ tenant/user scope check ] ──▶ agent decision logic (LLM via LlmPort, tools via ToolRegistryPort) ──▶ [ confidence gate ] confidence < threshold ─▶ autoEnforced=false ─▶ HumanReviewPort otherwise ─▶ autoEnforced=true ──▶ [ audit (append-only, PII-redacted) + observability ] ──▶ AgentOutput { decision{ action, confidence, rationale, autoEnforced } }

Design invariants

  1. The gate is in the runtime, not the agent. No agent approves its own decision.
  2. Tools are default-deny. A tool not in an agent's allowlist is unreachable.
  3. No self-escalation. An agent cannot widen its own authority at runtime.
  4. Every decision is auditable. Append-only, PII-redacted; BLOCK/ALERT carry explanations.
  5. The core is framework-free. Adapters depend on the core; the core depends on nothing.

Status

Increment 0 shipped the normative protocol spec, the Agent Contract schema, and ADR-0001..0011. Increment 1 added the Python 3.11+ reference runtime in src/agent_harness/ — a framework-free core (envelope, gate, registry, harness), Supervisor+Workers, port Protocols with in-memory adapters, and a contract loader. Increment 2 ships two real bindings/consumers: a Java 21 binding (java/, com.agentharness) with a grid migration adapter, and apex-sdlc running all seven of its SDLC phase agents on the harness, with a runnable reference journey that walks one project through every phase offline (the harness, not the agents, decides enforcement). Increment 3 completes the protocol in both languages: all four orchestration patterns (Pipeline, Fan-out, Debate/Consensus, and Supervisor+Workers with a governed planning turn) plus side-effect gating (T-5, §5.3, ADR-0011) — the harness refuses ungoverned write/external tool calls before they execute. Every binding maps 1:1 to the spec §9 conformance checklist (Python 74 · Java 54 tests). See progress.md.
